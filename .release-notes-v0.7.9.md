# v0.7.9 - Fluent settings dialog fix and runtime hardening

## 中文

### 亮点
**修复设置窗口崩溃**
- v0.7.8 完成 Fluent 迁移后，`FluentSettingsWindow` 是 `QObject`（QML 宿主）而不是 `QWidget`，把它作为 `QMessageBox` / `QProgressDialog` 的 `parent` 会被 PySide6 拒绝，导致设置中模型加载/测试/卸载全部崩溃。
- `MainWindow` 中 11 处 dialog 调用统一改为 `parent=None`（顶层对话框居中显示在当前屏幕）。
- 同时修复 `QProgressDialog` `cancelButtonText=None` 的 positional-only 类型违规。

**剪贴板线程安全**
- 转录完成后的粘贴在 worker 线程上执行，原先调用 `OleGetClipboard` / `OleSetClipboard` 会触发 `RPC_E_CANTCALLOUT_ININPUTSYNCCALL`（`0x8001010D`），而 `SetClipboardData` 在 worker 线程上恢复 registered 格式会引发 `0xC0000374` 堆损坏并杀掉进程。
- 非主线程上跳过 OLE 快照路径，并把 `_restore_all_formats` 限制为 `CF_UNICODETEXT`：文本是 STT 产物，牺牲图像/RTF 恢复换进程存活。

**修饰键状态对账**
- pynput low-level hook 偶尔在 UAC/UIPI 边界丢 KeyUp 事件，`current_vk_keys` 留下残留的 `VK_LWIN`/`VK_LMENU`，之后 alt+h 等组合再也匹配不上。
- 每次 KEYDOWN 用 `GetAsyncKeyState` 对账修饰键，把不再物理按下的 stale VK 丢掉。

**QML 引擎泄漏**
- 主窗口 `closeEvent` 只是 hide，进程退出时不会触发 settings 清理。
- 现在 `show_settings()` 把 `QApplication.aboutToQuit` 连到 `_release_settings_window`，进程退出时释放 `QQmlApplicationEngine`。

### 测试与 CI
- 新增 `tests/ui/test_main_window_dialog_flows.py`：白盒覆盖三个 model 信号处理器，dialog 父级类型由 PySide6 真值校验（不再是 Python wrapper 绕过）。
- 硬化 `tests/ui/conftest.py`：`qmessagebox_guard` 和新增的 `qprogressdialog_guard` 都按 PySide6 的 C++ 契约 assert `QWidget|None`。
- CI 之前 `pytest -m "not gui and not gpu and not e2e"` 整个 `tests/ui/` 都没跑。新增 `ui-tests` job（windows-latest，`QT_QPA_PLATFORM=offscreen`）。
- mypy 在 UI 表面打了 strict step（`src/sonicinput/ui/`，无 `|| true`），已知的 6 个问题模块在 `pyproject.toml [tool.mypy.overrides]` baseline 掉，新错误会让 CI 红。

### 发布产物
- `SonicInput-v0.7.9-win64.exe`
- 离线包仅在本地模型目录可用时生成。

### 升级步骤
1. 下载 `SonicInput-v0.7.9-win64.exe`。
2. 关闭旧版本并替换可执行文件。
3. 配置和历史记录保持兼容。

## English

### Highlights
**Settings dialog crash fix**
- After the v0.7.8 Fluent migration, `FluentSettingsWindow` became a `QObject` (QML host) rather than a `QWidget`. Passing it as the `parent` to `QMessageBox` / `QProgressDialog` was rejected by PySide6, breaking model load / test / unload from the settings window.
- All 11 dialog sites in `MainWindow` now pass `parent=None` so dialogs appear top-level on the active screen.
- Also fixed `QProgressDialog` rejecting `cancelButtonText=None` (positional-only `str`).

**Clipboard thread safety**
- Post-transcription paste runs on a worker thread. The old code called `OleGetClipboard` / `OleSetClipboard` from there, triggering `RPC_E_CANTCALLOUT_ININPUTSYNCCALL` (`0x8001010D`); `SetClipboardData` restoring registered formats from a worker also produced `0xC0000374` heap corruption that killed the process.
- The OLE snapshot path is now gated off main-thread, and `_restore_all_formats` on worker threads is restricted to `CF_UNICODETEXT`. Text is the STT product — image/RTF restore is sacrificed to keep the process alive.

**Modifier key state reconciliation**
- pynput low-level hooks occasionally miss a KeyUp across UAC/UIPI transitions, leaving stale `VK_LWIN`/`VK_LMENU` in `current_vk_keys` so later combos like `alt+h` never match again.
- On every KEYDOWN we now reconcile tracked modifiers against `GetAsyncKeyState` and drop any VK whose physical key is no longer pressed.

**QML engine leak on exit**
- The main window's `closeEvent` only hides; it never fires on process quit, so the cached `FluentSettingsWindow` (with its `QQmlApplicationEngine`) was never released.
- `show_settings()` now hooks `QApplication.aboutToQuit` to release the settings window on exit.

### Tests & CI
- New `tests/ui/test_main_window_dialog_flows.py`: whitebox coverage of the three model signal handlers; dialog parent types are validated against PySide6's real contract (no more Python-wrapper bypass).
- Hardened `tests/ui/conftest.py`: `qmessagebox_guard` and the new `qprogressdialog_guard` both assert parent is `QWidget|None`, matching PySide6's C++ contract.
- CI previously ran `pytest -m "not gui and not gpu and not e2e"`, meaning the entire `tests/ui/` directory never executed. A new `ui-tests` job runs the GUI suite on `windows-latest` with `QT_QPA_PLATFORM=offscreen`.
- mypy gained a strict step on `src/sonicinput/ui/` (no `|| true`). The 6 known-broken UI modules are baselined in `pyproject.toml [tool.mypy.overrides]`; any new type error fails CI.

### Artifacts
- `SonicInput-v0.7.9-win64.exe`
- Offline bundle only when a local model directory is available.

### Upgrade Steps
1. Download `SonicInput-v0.7.9-win64.exe`.
2. Close the old version and replace the executable.
3. Existing configuration and history data remain compatible.
